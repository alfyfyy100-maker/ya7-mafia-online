# أدوات «الهارب» — بناء بيانات الخريطة والاختبار

هذا المجلد ليس جزءًا من اللعبة. اللعبة كلها ملف واحد: `../index.html` (يعمل بلا خادم
ولا اتصال). هنا سكربتان فقط:

| الملف | الوظيفة |
|--|--|
| `build-geo.js` | يبني بيانات الخريطة من المصادر الحقيقية ويحقنها داخل `index.html` بين العلامتين `GEO-DATA-START` / `GEO-DATA-END` ويكتب `geo-data.json` و`geo-report.md` |
| `test.js` | يشغّل كل الاختبارات الإلزامية ويكتب `test-report.md` |

```sh
cd harib/tools
npm install          # topojson + polylabel + polygon-clipping + saudi-national-address + jsdom
npm run build        # ينزّل المصادر إلى raw/ عند الحاجة ثم يبني ويحقن
npm test             # node --check + سلامة البيانات + Haversine + محاكاة jsdom + القبض + الحقن
```

## مصادر البيانات — لا إحداثية واحدة من الذاكرة

1. **geoBoundaries (gbOpen) — السعودية**: حدود OpenStreetMap الإدارية كمضلّعات كاملة.
   `ADM0` حدود الدولة، `ADM1` المناطق الـ١٣، `ADM2` المحافظات (١٤٧ وحدة في لقطة OSM
   المبنية في ديسمبر ٢٠٢٣، بيانات المصدر يناير ٢٠٢٣). تُنزَّل من:
   `https://media.githubusercontent.com/media/wmgeolab/geoBoundaries/main/releaseData/gbOpen/SAU/ADM{0,1,2}/`
   الرخصة: ODbL / CC-BY-SA — © مساهمو OpenStreetMap. الصفحة تحمل الإسناد في ذيلها.
2. **حزمة npm `saudi-national-address`** (بيانات العنوان الوطني SPL): المناطق الـ١٣
   بمضلّعاتها الرسمية وأسمائها العربية، و٤٥٨١ مدينة بمركزها (خط عرض/طول) واسمها
   العربي والإنجليزي. منها تؤخذ أسماء المحافظات العربية ونقطة «مقرّ المحافظة».

## ما يُحسب حسابيًا (لا يدويًا)

- **المنطقة الأم** لكل محافظة: احتواء نقطة تمثيلية (polylabel) داخل مضلّع المنطقة
  الرسمي من SPL، مع مقارنة بمضلّع OSM ADM1 (خلافان فقط: غامد الزناد والبرك — اعتُمد
  الرسمي: الباحة وعسير).
- **الاسم العربي**: مطابقة اسم OSM الإنجليزي باسم مدينة SPL الواقعة داخل المضلّع نفسه
  (١٢٣ تلقائيًا + ٢٤ بجدول نقحرة `NAME_OVERRIDES` يُتحقق منه بالاحتواء أيضًا). تصحيح
  همزات فقط في `SPELLING`. لم يبقَ اسم بلا حلّ.
- **نقطة الإرساء** (تُحسب منها المسافات وتُرسم عليها النقطة): مركز مدينة المقرّ من SPL
  إن كان داخل المضلّع أو على بعد ≤ ٤ كم منه (السواحل: جدة، الجبيل، حقل)؛ وإلا مركز
  المضلّع البصري (حالة واحدة: وادي الفرع).
- **الفجوات**: فرق مضلّع الدولة عن اتحاد المحافظات. لقطة OSM ناقصة وحدة الدمام/الظهران
  (١٨٥٣ كم²) فأُضيفت من الهندسة نفسها — ليست مرسومة يدويًا. فجوات أخرى صغيرة (≤ ١٤٠ كم²
  على الحدود) تُترك وتُذكر في التقرير.
- **الجوار**: الأقواس المشتركة في طوبولوجيا TopoJSON (٤٠١ حدًّا) + تقارب رؤوس ≤ ٠.٨ كم
  (٣ حدود) + جسر واحد يربط جزر فرسان بجازان (٥٠ كم) حتى يصير الرسم البياني متصلًا.
  جوار المناطق مشتق من جوار محافظاتها.
- **الإسقاط**: مستوٍ بتصحيح `cos(lat0)` عند خط عرض ٢٤٫٥° — الوحدة كيلومتر تقريبًا.
  المسافات في اللعبة تُحسب بمعادلة Haversine على خط العرض/الطول لا على المستوي
  (الرياض ↔ جدة = ٨٥٠٫٨ كم).
- **التبسيط**: Visvalingam عبر TopoJSON على الأقواس المشتركة، فتبقى الحدود متطابقة
  بين الجيران بلا شقوق ولا تراكب (≈ ١٤٫٥ ألف رأس، ١٨٠ ك.ب).

## حدود معروفة

- عدد المحافظات يتبع لقطة OSM (١٤٧ + الدمام = ١٤٨ وحدة تشمل مدن المقرّ الثلاث عشرة).
  المحافظات المستحدثة بعد لقطة OSM لا تظهر. عند تحديث OSM يكفي حذف `raw/` وإعادة
  البناء. للمقارنة بقائمة رسمية راجع جدول الوحدات في `geo-report.md`.
- الاختبارات لا تقيس التوازن؛ التوازن يُضبط بعدد الجولات من شاشة الإعداد بعد لعب فعلي.

## نحو الأونلاين

حالة اللعبة `G` كائن واحد قابل للتسلسل (اللاعبون، المواقع، القراءات، الأحداث،
القدرات، السجل)، والمحرّك `Engine` منفصل عن الواجهة. في نسخة الأونلاين على بنية يا٧
(Durable Object لكل غرفة على نمط `RoomCommon`) يملك الخادم `G` كاملًا ويحسب القراءات
والعشوائية والقبض، ويرسل لكل لاعب نسخته المقتطعة فقط (موقعه وقراءته وما كُشف على
اللوحة)، والخريطة نفسها عامة. أي راوٍ أو تعليق بالذكاء الاصطناعي يمرّ عبر OpenRouter.
